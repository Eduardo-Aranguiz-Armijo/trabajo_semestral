# 👕 Trabajo Semestral: Microservicios Tienda de Ropa

Este repositorio contiene el ecosistema de backend completo para una plataforma de comercio electrónico de indumentaria, desarrollado bajo una **Arquitectura de Microservicios**. El sistema modulariza los dominios clave del negocio utilizando **Spring Boot**, **Spring Security (JWT)** y bases de datos relacionales, garantizando una infraestructura escalable, segura y tolerante a fallos.

## 📝 Descripción del Proyecto
El proyecto implementa un backend distribuido para una tienda de ropa en línea. La solución divide las responsabilidades del negocio en microservicios autónomos que interactúan entre sí de manera síncrona mediante peticiones HTTP no bloqueantes utilizando **WebClient**. 

La seguridad es transversal: se cuenta con un mecanismo de autenticación y autorización stateless centralizado basado en tokens **JWT (JSON Web Tokens)** y **Spring Security**. El acceso a los recursos está restringido mediante roles (`ADMIN` / `USER`), requiriendo que los tokens firmados mediante algoritmo HMAC-SHA256 viajen adjuntos en la cabecera `Authorization: Bearer` de cada solicitud para proteger los flujos del carrito y del negocio.

## 🏗️ Arquitectura y Funcionalidades del Sistema

A partir del análisis del código fuente, el ecosistema cuenta con los siguientes módulos distribuidos y sus responsabilidades técnicas:

### 1. 🔐 Microservicio de Usuarios (`ms-users`)
* **Puerto Base:** `8081`
* **Funcionalidades:**
  * **Registro Global (`/api/v1/auth/register`):** Permite el alta de credenciales encriptadas con `BCryptPasswordEncoder` y propaga los datos hacia el servicio de clientes.
  * **Autenticación (`/api/v1/auth/login`):** Valida las credenciales en la base de datos MySQL (`db_auth`) y emite tokens JWT con claims personalizados (`role`, `username`, `id`).
  * **Filtro de Seguridad (`JwtAuthFilter`):** Intercepta peticiones protegidas para poblar el contexto de Spring Security.
  * **Persistencia:** Mapeo relacional con Hibernate/JPA. Cuenta con prevención de conflictos de palabras reservadas del motor (escape de la columna ``` `role` ```).

### 2. 🛒 Microservicio de Carrito (`ms-carrito`)
* **Puerto Base:** Ejecución dinámica o acoplada al API Gateway.
* **Funcionalidades:**
  * **Control de Carritos (`/api/v1/cart`):** Operaciones CRUD completas para carritos individuales y sub-ítems (`CartItem`) protegidas mediante anotaciones de seguridad por método (`@PreAuthorize("hasRole('ADMIN')")`).
  * **Consultas Distribuidas (Integración WebClient):**
    * `ClienteClient`: Obtiene los datos del cliente según su UID (`/api/v1/customer/user/{userId}`).
    * `ProductClient`: Consulta el catálogo para validar precios y detalles del producto (`/api/v1/products/{id}`).
    * `InventoryClient`: Verifica existencias físicas críticas en tiempo real antes de añadir prendas al carrito (`/api/v1/inventory/product/{productId}`).

### 3. 👥 Microservicio de Clientes (`ms-customers`)
* **Funcionalidades:**
  * Modela los datos de perfil de los compradores reales de la tienda de ropa (RUT, dirección, teléfono, correo) vinculándolos inequívocamente a un `userId`.
  * Expone los endpoints de consumo requeridos por el carrito de compras.

### 4. 💳 Microservicio de Métodos de Pago (`ms-payment-methods`)
* **Funcionalidades:**
  * Gestión segura y persistencia de tarjetas de crédito/débito (`PaymentMethod`) asociadas a los clientes.
  * Almacenamiento de metadatos críticos para pasarelas de pago (`cardHolder`, `cardNumber`, `expirationDate`, `cvv`).

### 5. 👚 Microservicio de Productos (`ms-products`)
* **Funcionalidades:**
  * Control del catálogo de vestuario (`Producto`) incluyendo nombre, descripción detallada, precios y asociación a categorías (`categoryId`).

## 🛠️ Herramientas y Tecnologías Utilizadas
- **Java 17** o superior.
- **Spring Boot 3.x** (Framework base).
- **Spring Security** (Aseguramiento perimetral y de métodos).
- **Spring Data JPA** (Persistencia y abstracción SQL).
- **Spring WebFlux (WebClient)** (Comunicación interna distribuida).
- **Flyway Migrations** (Evolución y versionamiento automatizado de esquemas de Base de Datos).
- **MySQL Driver** & **Lombok**.

## 💥 Manejo Centralizado de Errores
El sistema implementa interceptores globales mediante `@RestControllerAdvice` (`GlobalExceptionHandler`) para unificar las respuestas ante fallos de negocio bajo el formato estructurado `ErrorResponse`:
- `InvalidCredentialsException` / `BadCredentialsException` ➡️ **401 Unauthorized**
- `UserNotFoundException` / `CartNotFoundException` ➡️ **404 Not Found**
- `MethodArgumentNotValidException` ➡️ **400 Bad Request** (Validaciones de inputs)
